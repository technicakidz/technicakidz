【ツール】

GitHub / Slack / Notion / BigQuery (データ転送) / Storage Transfer Service / GCS / Datadog / Tableau / Looker Studio

【プロダクトが属する業界】

広告・マーケティング業界

【プロダクト概要】

1st Party Data を活用した DMP (Data Management Platform)。

広告施策に対するコンバージョン最適化や、データ蓄積を強みとしたユーザー分析レポートを提供するWEB / APP広告の効果測定サービス。

【チームでの役割】

KPI達成に向けプロダクトを活用した施策案件の遂行。開発部門とプロダクトセールスの橋渡し。

機能実装要望の仕様定義、設計、リリース後の挙動チェック、アナウンスなど本格的なプロダクトマネージャー業務を担当。開発部長とも協働しプロダクトをより良くするためのPJロードマップ策定などを主導。

また、BigQuery を活用したデータ分析業務/相談やSQLレビューを中心的に担うことによるメンバーのデータリテラシー向上への寄与。

主な実績：

- dev含むプロダクトチームのファシリテーション
- PdMとしてプロダクトの既存/新規機能を刷新するメジャーアップデートにコミット
- プロダクトチームのチーミング、biz と dev を近づけるはたらきかけ
    - チーム関連ミーティングのファシリテーション、アイスブレイク等による共通の話題作り
    - 主催の社内勉強会では biz、dev 隔たりなくフレキシブルなテーマに
      - 自分から times などでネタを拾い依頼
    - エンジニアに代わり業務で触れる Google Cloud サービスの概要説明
    - プロダクトが向かう方向性や果たすべき役割をディスカッションするボード会
    - ローコード人材の育成を主導しレビュワーに開発メンバーをアサインするなどの支援
- 共通の用語定義から前提を揃えたドキュメンテーション
- プロダクトの機能活用を目的とした技術知識の必要な専門性の高い周辺ツールの業務巻取り
  - Adjust export loader(GCS + TransferService + CloudScheduler + CloudRun + BQ)


【課題と自身が工夫したこと】

機能開発において、形骸化した会議体を改善し企画段階からエンジニア出席のもと目標設定と要件整理を進めた。これによりエンジニアが機能自体の有用性をより意識できるようになった。能動的にサービス利用を提案するような、ビジネス、エンジニア双方向でプロダクトに向きあう雰囲気作りを醸成した。

プロダクト改善のためのユーザーヒアリングでは、ユーザーの利用状況分析から社内ユーザへのインタビューやデモ実装の説明会などを実施。よりフィードバックを多角的に理解する工夫をした。

自身がチームマネージャー (ピープルマネジメント) でもあるため、エンジニアやビジネスメンバーとの1on1を通し業務外の対話を継続的に実施。
ビジネス側へGitHubの利用を浸透させ開発体制整備を促進したことで、ビジネスサイドのデータ分析業務におけるエンジニアサポートの円滑化を実現。  
また以前よりレポーティング業務が、案件依存かつ個人プレーであったチーム課題もあった。そのため GitHub Projects を導入し、プロジェクトタスクを共有、会議体を調整することで解決へ進めた。


【成果】

プロダクトのROIや利益率維持に貢献。社内のメンバーが担当するプロダクト導入コストの抑制や、効率的な分業化を推進。  
課題であった複雑な設定入力フォームを、細かいUX改善タスクの着実な遂行により運用工数削減に寄与。大きなスケジュール遅延を起こさず、新規機能の開発を推進。

また、プロダクト提供の最重要観点である安定供給面において、広告データ計測と施策状況のモニタリング体制を整備し、エラー検知する仕組みを整えたことで品質担保とCS向上に貢献した。

プロダクトが対応する広告媒体数を拡充し、新規で複数媒体を追加し競合優位性を強化した。


チーム成果として、GitHubに馴染みのないメンバーがプルリクエスト形式でクエリレビュー依頼をするところまで育成し、より具体かつ精度の高い分析レポートを顧客提供できるようにした。  
結果的にビジネスサイドはエンジニアとの距離が近づき、エンジニア出身の自身が dev と biz の翻訳家としてバリューを発揮した。
